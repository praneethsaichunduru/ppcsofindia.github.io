Know About PPCs: prototypes

Five ways to rebuild the page. Each one uses the real list of PPC pages, so open them and try them.

A

Sticky state bar

The page stays one long scroll, as now, but a bar of state chips follows you, and highlights the state you are reading.

  • Smallest change from today
  • States with no article are hidden (or dashed)
  • Still a long page
Open prototype A
B

Regions and collapsible states

States are grouped into North, South, East and so on, each with a count and a small bar showing the mix of post-office types. Open only the states you want.

  • Short page, easy to scan
  • Images load only when a state opens
  • #karnataka opens a state directly
Open prototype B
C

Search and filter cards

One grid of every PPC. Search a place, post office or pincode, filter by state and by post-office type (the same four colours as the PO Map), and sort by date or name.

  • Best for finding one PPC
  • Loads 48 cards at a time
  • Loses the state-by-state reading flow
Open prototype C
D

Sidebar explorer with shareable links

A state list (grouped by region, with counts) on the left; cards, post-office type filters and a search on the right. On phones the list becomes a drop-down.

  • Combines A, B and C
  • The address bar holds the view, e.g. #state=Karnataka&rank=2
  • The PO Map and Dashboard can link straight into it
Open prototype D
E

Tile map

Every state is a tile placed roughly where it sits on the map, shaded by how many articles it has. Tap a tile and its PPCs open below.

  • Friendly entry point for visitors
  • Fun, but a cartogram, not a true map
  • Works well on top of D
Open prototype E
Suggested direction: D as the page, with E as the opening panel above it, and the empty states hidden. That keeps the state-by-state browsing of the current page, adds search, and gives other pages (PO Map, Dashboard, the PPC List) a way to link to one state or one post-office type.

Notes

  • All five read data.js, a snapshot built from the current blog-main.html and the blog pages (state, name, image, post office, pincode, date). The real page would not need this file: it could keep its own entries, or build them from the same sources.
  • Scans that are not in pictures/ppcs yet show a "Scan coming soon" box instead of a broken image.
  • None of the prototypes use jQuery or Bootstrap; they are plain HTML, CSS and JavaScript with the site's theme, so dark mode works.
  • These files sit in prototypes/know-about-ppcs/ and can be deleted without affecting the site.
